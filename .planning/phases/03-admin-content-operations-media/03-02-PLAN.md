## Implementation Details

### Media Upload Pattern

- Server Action accepts `FormData` with file
- Validate: file type (image/jpeg, image/png, image/webp), max size (4MB)
- Write to `public/uploads/{timestamp}-{sanitized-filename}`
- Store metadata in `data/media.json`: id, filename, url, altText, uploadedAt, size, type
- Return `{ success: true, media: MediaItem }` or `{ error: string }`

### Profile Data Flow

- `getSchoolProfile()` reads from `data/profile.json` with seed data fallback
- `updateSchoolProfile(input)` merges changes into profile and writes
- Edit form pre-fills with current data from service
- After save: `revalidatePath("/")` to update homepage

### Programs/Facilities Editor

- List view: table/cards with edit/delete per item
- Create/edit form: name, description, icon (programs); name, description, icon (facilities)
- Uses file-storage.ts for persistence
- After save: `revalidatePath("/programs")` to update public page

### AdminShell Nav Updates

After "Pengumuman":
```tsx
<a href="/admin/profile" className="...">Profil Sekolah</a>
<a href="/admin/media" className="...">Media</a>
```

### No External Dependencies

- Uses `fs` for file operations
- Uses file-storage.ts from 03-01
- Uses Next.js Server Actions for form handling
- Uses `revalidatePath` for cache invalidation
